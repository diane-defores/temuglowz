# Bug Record: BUG-2026-07-12-001

## Summary

- Title: Astro site CI runs on an unsupported Node.js version
- Current status: `closed`
- Severity: `medium`
- Owner: codex
- Next command: `none`

## User Story

En tant qu’opératrice du dépôt TemuGlowz, je veux que la validation CI du site Astro utilise une version Node.js supportée, afin que les contrôles de type, tests et build s’exécutent réellement avant une livraison.

## Reproduction

- Preconditions:
  - The `site-checks` GitHub Actions workflow runs for a TemuGlowz commit.
  - The workflow provisions Node.js `20.19.0`.
  - The site uses Astro 7.
- Steps:
  1. Trigger the `site-checks` workflow for the affected commit.
  2. Observe the Astro setup/check command on the GitHub Actions runner.
  3. Inspect the job result before the site typecheck, tests, and build complete.

## Expected Behavior

- The CI workflow provisions Node.js `>=22.12.0`, then completes Astro typecheck, tests, and build so the site change receives meaningful validation.

## Observed Behavior

- The workflow runs on Node.js `20.19.0`.
- Astro rejects that runtime because Astro 7 requires Node.js `>=22.12.0`.
- The site-checks job fails before typecheck, tests, and build can provide validation.

## Evidence

- Redacted-safe CI observation from `405-sg-prod`: the `site-checks` workflow for commit `d7cb609` failed with the runtime compatibility message that Node.js `20.19.0` is unsupported and Astro requires `>=22.12.0`.
- Redacted-safe production observation from `405-sg-prod`: Vercel production built the Astro site successfully, confirming that the failure is specific to the CI runtime configuration rather than an observed production build failure.
- Hosted repair retest from `405-sg-prod` on commit `d0248771a3e14965be69691e75aa5cf4c474b8e8`: GitHub Site Checks run `29231129575` and Android run `29231129638` both completed successfully; the Vercel preview deployment is READY with Astro and Node 24.x runtime; production returns HTTP 200 with zero redirects and public `TemuGlowz` content.
- No secrets, tokens, cookies, private payloads, private headers, or personal data are recorded.
